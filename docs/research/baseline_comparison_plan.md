# 표 구조 인식과 RAG 시스템 비교를 위한 베이스라인 모델 및 평가지표 제안

## 1. 표 구조 인식(TSR) 베이스라인 모델

표 구조 인식(테이블 구조 복원)은 다양한 접근법이 존재하며, GraphTSR 이후에는 전통적인 부분 기반 방식에서 전체 구조를 직접 예측하는 방식으로 발전하였다. 연구 가설과의 비교를 위해 다음 모델을 기본 베이스라인으로 제안한다.

| 분야 | 대표 모델 | 핵심 아이디어 및 특징 | 평가지표 |
| :--- | :--- | :--- | :--- |
| **셀 간 관계 중심** | **GraphTSR** (2019) | PDF 테이블에서 셀 박스를 노드로 하고 인접 관계를 간선으로 하는 그래프를 입력으로 사용하여 GNN으로 관계를 예측하는 방법. 복잡한 병합 셀이 있는 테이블에 강점을 보인다. | - 인접 행렬 기반 정밀도·재현율·F1<br>- 논리적 위치(행/열) 정확도 |
| **표 그리드 재구성** | **TGRNet / LORE** (2022~2024) | 두 단계로 셀의 공간 좌표와 논리 좌표를 순차적으로 예측하거나 Cascade 구조를 사용하여 논리 위치를 회귀하는 방법. 최근 LORE/LORE++은 논리 위치와 공간 위치를 함께 회귀하여 오류 누적을 줄인다. | - IOU=0.5 조건의 물리 좌표 F1<br>- 논리적 위치 정확도<br>- 인접 관계 F1<br>- BLEU·TEDS (표를 HTML 트리로 변환 후 트리 편집거리로 평가) |
| **엔드투엔드/원스테이지** | **TableCenterNet** (2025) | CenterNet 프레임워크를 활용하여 공간 위치와 논리 위치를 병렬 회귀하는 원스테이지 네트워크. 셀 위치와 행/열 번호를 동시에 학습하여 복잡한 테이블에 강점을 보인다. | - 셀 공간 좌표의 정밀도·재현율·F1 (IOU 0.5)<br>- 논리 위치 정확도 및 인접 관계 F1<br>- TEDS 기반 구조 유사도 |
| **마스크/마크업 예측** | **LGPMA** (2021), **EDD** (2020) | LGPMA는 지역·전역 피라미드 마스크 정렬을 통해 스팬셀을 복원하고 TEDS‑Struct 점수를 높였다. IBM의 EDD는 구조 디코더와 셀 디코더를 분리하여 HTML 마크업을 직접 생성하고 PubTabNet에서 TEDS 평균 88.3%를 달성했다. | - TEDS / TEDS‑Struct (트리 편집거리 기반)<br>- 인접 관계 F1 또는 BLEU |
| **경량 네트워크** | **TableNet**, **CascadeTabNet** 등 | 경량 CNN·Transformer로 셀 검출 후 규칙 기반으로 구조를 복원하는 초기 딥러닝 방법. 비교적 단순한 테이블에 적용된다. | - 물리 좌표 F1, 가중 F1 (여러 IOU 임계값 평균)<br>- TEDS 또는 BLEU |

### 평가지표 설명

- **정밀도·재현율·F1 (Physical Coordinates)**: 셀 위치 검출의 정확도를 IOU 기준으로 평가한다. TableCenterNet 논문에서는 IOU=0.5에서 정밀도·재현율·F1을 사용하였다.
- **논리적 위치 정확도**: 각 셀의 행·열 번호를 정확히 예측했는지 평가하는 지표이다.
- **인접 관계 F1**: 셀 쌍의 인접 여부(동일 행/열 접속)를 분류한 결과를 기준으로 F1을 계산한다.
- **TEDS (Tree Edit Distance Similarity)**: HTML 트리 기반으로 예측 구조와 정답 구조 간의 편집거리를 계산해 0~1 범위의 유사도로 표현한다. TEDS는 전통적인 인접 F1보다 구조적 오류에 민감하고 문자 수준 오류는 선형적으로 반영한다. LGPMA와 EDD 등은 TEDS 또는 TEDS‑Struct를 사용한다.
- **BLEU**: 마크업 시퀀스 예측 모델에서 참조 HTML과 예측 HTML 간의 n‑그램 유사도를 측정한다.
- **가중 F1 (WAvg.F1)**: 여러 IOU 임계값(0.6/0.7/0.8/0.9)에서 측정한 F1을 평균하여 평가한다.

## 2. RAG 시스템 및 표 기반 QA 베이스라인

표 기반 질문응답을 위해서는 검색–생성 파이프라인 전체를 평가해야 한다. 최근 연구들은 아래와 같은 베이스라인 모델과 지표를 사용한다.

| 분류 | 베이스라인 / 프레임워크 | 특징 | 평가지표 |
| :--- | :--- | :--- | :--- |
| **기본 RAG** | **NaiveRAG** | 테이블을 Markdown 같은 문자열로 평탄화하여 일반적인 RAG 파이프라인을 적용한다. TableRAG 논문에서 비교 대상 중 하나로 사용된다. | - LLM‑as‑Judge 정확도: Qwen‑2.5‑72B 등 LLM을 이용해 정답 여부를 0/1로 평가하는 정확도. |
| **프롬프트 기반** | **ReAct** | LLM에게 검색과 추론을 통합하도록 프롬프트를 설계하여 사전 지식 없이 테이블을 검색·추론한다. TableRAG 논문에서 표 기반 QA의 대표적인 기준선으로 사용된다. | - LLM‑as‑Judge 정확도<br>- 응답 지연시간 및 합리화 분석 |
| **코드 실행 기반** | **TableGPT2** | LLM이 Pandas 등 코드 조각을 생성하여 테이블을 조작하고 답을 계산한다. 복잡한 연산에 강하지만 실행 환경이 필요하다. | - LLM‑as‑Judge 정확도<br>- 실행 성공률 |
| **강화 RAG** | **TableRAG** (2025) | SQL 기반으로 테이블을 데이터베이스에 저장한 후 질문을 분해하고 SQL을 실행하여 중간 답을 생성한다. TableRAG는 NaiveRAG, ReAct, TableGPT2보다 정확도가 10% 이상 향상됨을 보고한다. | - 정확도(Exact Match 또는 LLM‑as‑Judge)<br>- 다중 테이블 문제를 위한 HeteQA/HybridQA EM |
| **그래프 기반** | **GTR** (Graph‑Table‑RAG, 2025) | 여러 테이블을 하이퍼그래프로 표현하고 coarse‑to‑fine 검색과 그래프‑인식 프롬프트를 사용하여 교차 테이블 QA 문제를 해결한다. | - 테이블 검색 정확도와 recall 개선(1.2~11.4% 정확도, 1.5~12.5% 재현율 향상)<br>- 다운스트림 QA 정확도 (HybridQA/MultitableQA) |
| **기본 QA 모델** | **HybridQA Baselines** | HybridQA 데이터셋에서 표 전용, 텍스트 전용, 표+텍스트 결합 모델을 비교하며, EM(Exact Match) 점수를 사용한다. 논문에서는 표+텍스트 모델이 EM 40% 이상을 달성했으나 인간 수준보다 낮음을 보고한다. | - EM (정답과의 완전 일치율)<br>- F1 (정답 세트와의 부분 일치율) |
| **다중 모드 평가도구** | **DynamoEval**, **RAGAS** | 회수된 표의 적합성(컨텍스트 관련성)과 답변의 정확성·충실도를 평가하기 위한 LLM‑judge 기반 도구. DynamoEval 연구에서는 정확도, 정밀도, 재현율을 사용해 기존 RAG 평가도구보다 우수함을 보여준다. | - 정밀도·재현율·정확도 (컨텍스트 및 답변의 good/bad 분류)<br>- LLM‑judge를 활용한 faithfulness 평가 |

### RAG 평가 지표

- **정답 정확도 / Exact Match (EM)**: 질문에 대한 답이 정답과 완전히 일치하는 비율. HybridQA 등 QA 벤치마크에서 사용된다.
- **LLM‑as‑Judge Accuracy**: LLM이 응답의 정답성을 판단하여 0/1 점수를 부여하는 방법. TableRAG 연구에서 여러 베이스라인의 전체 정확도를 비교할 때 사용되었다.
- **컨텍스트 Recall/Precision@k**: 검색 단계가 관련 표를 얼마나 많이 회수하는지 평가하는 지표로, multi‑table RAG 논문에서 recall 개선을 보고한다.
- **답변 Faithfulness**: LLM이 제공한 답이 주어진 컨텍스트에 근거하는지 평가하는 지표. DynamoEval 등의 평가도구가 LLM‑judge를 활용하여 측정한다.
- **응답 지연시간**: SQL 실행이나 그래프 탐색을 포함한 시스템의 효율성을 비교할 때 사용한다. TableRAG 연구에서도 고려되었다.

## 3. 종합 제언

사용자가 제안한 RCA(Row‑Column Attention) 방식의 우수성을 입증하려면 기존 표 구조 인식 모델과 RAG 파이프라인 모두에 대해 동일한 데이터셋과 정량적 지표를 활용해 비교해야 한다. 아래와 같이 설계할 수 있다.

1. **데이터셋 선택**: PubTabNet, SciTSR, ICDAR-2013/2019, TableGraph-24k 등 다양한 복잡도를 가진 공개 데이터셋을 사용하여 구조 인식 성능을 측정한다. RAG 비교를 위해서는 HybridQA, WikiTableQuestions, MULTITABLEQA, HeteQA와 같은 표 기반 QA 데이터셋을 활용한다.
2. **베이스라인 모델**: GraphTSR, LORE/LORE++, TableCenterNet, LGPMA, EDD 등 구조 인식 모델과 NaiveRAG, ReAct, TableGPT2, TableRAG, GTR 등 RAG 시스템을 구성하여 비교한다.
3. **평가지표**:
    - **구조 인식 단계**: TEDS/ TEDs‑Struct, 논리 위치 정확도, 인접 관계 F1, 물리 좌표 F1(다중 IOU), BLEU 등을 측정한다.
    - **RAG 단계**: 검색의 recall@k, LLM‑judge 정확도/EM, 답변 faithfulness, 실행 시간 등을 측정한다.

이러한 베이스라인과 지표를 활용하면 새롭게 제안한 RCA 알고리즘이 전역적 그리드 인식을 통해 기존 방법 대비 구조적 오류 감소와 RAG 정답률 향상을 얼마나 달성했는지 객관적으로 검증할 수 있다.
